Each token is colored by its g-value: whether the secret key's coin flips for that exact sequence of tokens came up in the watermark's favor. One token proves nothing; the verdict comes from hundreds of them together. Hover a token for its numbers.

The z-score recomputed after each scored token. Watermarked text climbs steadily, because every token adds a little evidence and the score grows with the square root of the length. Unwatermarked text wanders near zero. This is why short texts can't be judged.

Each bar is that word's share of the final z-score, summed over every time it appears (the bars add up to the total). Words that sit in a "lucky" n-gram for this key push the score up. Change them and the score drops.

The detector only ever looks at short runs of exact tokens, never at meaning. A good paraphrase shares few runs with the original story, yet the meaning is the same. That is why the watermark has to be added while the model writes: it can't be read off the ideas.

The secret key

In real deployments this stays private. Anyone holding it can detect the watermark, and forge it on text the model never wrote.

These integers are the keys, one per tournament layer. Each candidate token's g-value in layer i is a pseudo-random bit computed from a hash of (the previous tokens + the candidate + key i).

Wrong-key test: press Random key next to the detector's Key box. The same watermarked text then reads as noise, on every chart. SynthID is not an "AI text detector": it only recognizes text made with its own key. Changing just one number of this key only breaks that one tournament layer, so the score drops but doesn't vanish.
